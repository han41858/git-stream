# GitStream — 개발 명세서 v0.2

> Explore the flow of Git history.

## 1. 개요

GitStream은 GitHub 저장소의 커밋과 브랜치 관계를 **세로형 그래프**로 시각화하는 오픈소스 웹앱입니다. GitHub Insights → Network와 비슷한 Git DAG 뷰어이지만, 세로 스크롤과 미니멀한 인터랙션을 중심으로 설계합니다.

- 저장소: `han41858/git-stream`
- 형태: 모바일 대응 읽기 전용 SPA
- 배포: 정적 호스팅, 자체 백엔드·데이터베이스 없음
- 핵심: 실제 커밋의 부모·자식 관계를 정확히 표시
- 범위: 첫 버전에서는 조회와 시각화에 집중

## 2. MVP 기능

### 2.1 저장소 입력
- `https://github.com/owner/repo`, `owner/repo` 입력 지원
- 저장소 메타데이터, 기본 브랜치 및 브랜치 참조 조회
- 저장소 식별자를 URL에 반영하여 링크 공유 및 새로고침 후 복원
- 잘못된 주소, 미존재·비공개 저장소, 네트워크 오류 안내

### 2.2 공개·비공개 저장소
- Public: 별도 인증 없이 GitHub REST API 사용
- Private: 사용자가 직접 입력하는 **fine-grained PAT**로 조회
- 토큰 패널에서 토큰이 없을 때의 한도(IP당 시간당 약 60회, 같은 네트워크 사용자와 공유)와 토큰 사용 시 한도(시간당 약 5,000회)를 안내
- PAT 발급 안내: 저장소 선택 및 `Contents: Read-only` 권한; PR 추천 집계에는 `Pull requests: Read-only`도 필요
- 토큰은 브라우저 메모리에만 유지하고 제거할 수 있어야 함
- 토큰을 URL, localStorage, sessionStorage, IndexedDB, 로그, 분석 서비스에 저장하거나 노출하지 않음
- 인증 토큰은 GitHub API 요청에만 사용
- 토큰이 잘못되었거나 접근 권한이 없을 때 안내
- GitHub 계정 로그인·OAuth·GitHub App은 MVP 제외

### 2.3 세로형 커밋 그래프
- 커밋을 작은 원형 노드, 부모 관계를 선으로 표시
- 브랜치 분기와 Merge Commit의 다중 부모 관계 표시
- 하나의 SHA를 그래프에서 중복 노드로 표시하지 않음
- 색상은 배치 열 번호와 분리해 경로별로 유지하며, 분기 경로와 그 머지 연결선의 색상이 합류 전까지 중간에 바뀌지 않음
- 페이지 추가나 레인 위치 변경 시에도 기존 경로 색상을 유지. **브랜치 참조와 배치 레인은 같은 개념이 아님**
- 텍스트를 최소화해 노드 및 선 관계에 집중
- 그래프 방향: **최신 → 과거(기본)** / **과거 → 최신** 전환
- Git DAG의 위상 순서를 보존하고, 커밋 날짜만으로 부모·자식 순서를 결정하지 않음
- 시간 방향 변경은 동일한 관계를 반대 방향으로 표시하는 기능이며 데이터 자체를 바꾸지 않음

### 2.4 커밋 인터랙션
- 데스크톱 Hover, 모바일 Tap으로 상세 정보 표시
- SHA(축약), 메시지, 작성자, 날짜, GitHub 원본 링크
- 커밋 선택 상태 유지 및 원본 커밋 페이지로 이동
- 아직 조회하지 않은 이력이나 불완전한 관계는 완전한 데이터처럼 표현하지 않음

### 2.5 브랜치
- `main` → `master` → 저장소 기본 브랜치를 목록 앞에 고정하고 중복 이름은 한 번만 표시
- 초기 선택도 같은 우선순위를 적용
- 추천은 우선 브랜치를 포함해 최대 30개, 나머지는 최근 90일간 병합 PR의 대상 횟수 순
- 추천 목록을 열 때 PR을 소규모로 집계하고 부분 집계 상태와 이어서 집계할 수 있는 버튼 제공
- 현재 존재하는 브랜치만 추천하고, 목록 밖의 브랜치는 검색 및 정확한 이름 조회로 선택 가능
- 기본 브랜치 및 조회 가능한 브랜치 HEAD 표시
- 기준 브랜치를 선택하며 그 HEAD의 첫 번째 부모를 따라가는 경로는 직선 레인에 고정
- 다른 브랜치 및 병합된 이력은 별도 레인에 배치하고 실제 부모 SHA 관계로만 연결
- 공통 조상이 조회되지 않거나 관련 없는 이력은 임의로 기준선에 연결하지 않음
- 스크롤 중 보이는 브랜치 경로 가까이에 이름을 유지하고 경로가 화면을 벗어나면 숨김
- 머지 연결선과 화면을 가로지르는 곡선도 이름 표시 대상이며, 가까운 이름 배지는 겹치지 않게 배치
- 다른 브랜치의 고유 경로 이름은 다른 경로 합류 지점까지 표시. 처음부터 기준선에 있는 참조는 보이는 공통 이력에서 함께 표시
- 여러 브랜치가 같은 커밋을 가리킬 수 있음
- 브랜치가 삭제되면 참조 이름이 남지 않을 수 있으므로 복원 가능하다고 가정하지 않음

### 2.6 반응형
- 데스크톱: 세로 스크롤, Hover 상세 정보
- 모바일: 자연스러운 세로 스와이프, Tap 상세 정보, 필요한 경우 가로 이동
- 터치 대상 영역은 실제 노드보다 넉넉하게 구성
- 모바일의 필수 동작은 Hover에 의존하지 않음
- 밝은/어두운 테마, 시스템 설정 기본

## 3. UI 원칙

- 저장소 입력과 그래프를 중심으로 단순하게 구성
- 그래프를 전체 뷰포트에 표시하고 저장소·기준 브랜치·방향 컨트롤은 작은 오버레이로 제공
- 상세 정보는 노드 선택 시 여닫을 수 있는 패널로 표시
- 모바일 그래프의 메시지·SHA·작성자 텍스트는 숨기고 브랜치 이름만 유지
- 브랜치 선택 및 시간 방향 전환은 간결한 컨트롤로 제공
- 시간 방향은 상단의 `↓ Older` / `↓ Newer` 토글로 표시하고 화살표는 아래로 고정. 툴팁·접근성 이름으로도 현재 방향 안내하고, 로딩은 문구 대신 인디케이터로 표시
- 과거 이력 스크롤 안내 문구는 표시하지 않음
- 우주·궤도 이미지는 점과 선의 시각적 느낌에만 은은히 반영
- 과도한 애니메이션, 배경 파티클, 3D 효과 등 장식 배제

- Force Simulation은 사용하지 않음
- Three.js, PixiJS, WebGL은 초기 범위 제외
- Web Worker는 측정 결과 레이아웃 계산으로 UI가 지연될 때 검토

## 5. 데이터 처리 및 정확성

### 5.1 모델
- Commit: SHA, 부모 SHA 목록, 메시지, 작성자, 작성·커밋 일시, GitHub URL
- Branch: 이름, HEAD SHA, 기본 브랜치 여부
- 커밋은 SHA를 기준으로 중복 제거하고, 브랜치는 커밋을 가리키는 참조로 취급

### 5.2 API 및 로딩
- GitHub REST API의 페이지네이션을 사용하고 요청당 최대 100개 커밋 조회
- 기본 브랜치의 최근 이력을 우선 표시한 다음 필요에 따라 다른 브랜치와 과거 이력 추가 조회
- 다른 브랜치에만 존재하는 커밋을 누락한 채 전체 그래프라고 표현하지 않음
- API 중복 요청 최소화, 요청 취소, 오류 시 재시도 지원
- 비인증 호출의 낮은 API 제한과 인증 호출 제한을 고려
- 초기 전체 이력을 다운로드하지 않음
- 화면에 보이는 미완료 브랜치의 미조회 부모 경계가 나타나면 해당 브랜치의 다음 페이지를 자동 로딩
- 가장 긴 브랜치나 전체 그래프의 끝을 기다리지 않으며, 실제 루트·이미 조회한 합류는 로딩 조건에서 제외
- 과거 이력 방향의 스크롤 경계에서 추가 브랜치 참조도 자동 페이지 로딩
- 기본 브랜치와 다른 브랜치를 소규모 배치로 조회하고 중복 요청을 방지
- 조회 종료 시 자동 로딩을 멈추며, 오류 시 재시도 전까지 자동 요청을 중단
- 아직 조회되지 않은 부모·분기 경계는 시각적으로 구분
- 새 데이터가 합쳐져도 기존 노드의 불필요한 레인 이동 최소화

### 5.3 렌더링과 성능
- Canvas 2D로 현재 뷰포트와 소량의 여유 영역만 렌더링
- 가상 스크롤/점진적 로딩으로 대량의 DOM·노드 생성 회피
- 스크롤·선택·크기 변경 등 필요한 시점에 다시 그리기
- devicePixelRatio 반영
- 메모리 캐시 우선, 영속 캐시는 필요성이 확인될 때 검토
- `angular/angular` 같은 대형 공개 저장소로 성능 검증
- 커밋 1천/1만/10만 개 수준의 합성 데이터 테스트를 단계적으로 고려하되, 조회·렌더링 한계는 실측해 결정

### 5.4 DAG 레이아웃
- 부모 SHA 관계를 정확하게 연결
- 다중 부모 Merge Commit과 공유 커밋 처리
- 선 교차, 불필요한 좌우 폭, 레인 급변 최소화
- 커밋 timestamp를 기준으로 단순 정렬하여 부모보다 자식이 잘못 배치되는 문제 방지
- 부분 데이터가 추가될 때의 레이아웃 안정성을 고려

## 6. 오류와 빈 상태

- 잘못된 입력
- 없는 저장소 / 비공개 또는 권한 부족
- 잘못된 PAT
- API rate limit: 권한 오류와 구분하고 초기화 시각 안내 및 이른 재시도 방지
- 네트워크 장애 및 일부 요청 실패
- 빈 저장소 / 커밋 없음
- 일부 브랜치 또는 부모 커밋 미조회

오류는 이해 가능한 메시지로 표시하고, 토큰과 민감한 응답 내용은 노출하지 않습니다.

## 7. 테스트

최소한 다음 그래프 시나리오에 대한 자동 테스트를 작성합니다.

1. 단일 브랜치 선형 이력
2. 브랜치 분기
3. 두 브랜치 병합
4. 다중 부모 Merge Commit
5. 여러 브랜치가 공유하는 커밋
6. 시간 방향 전환
7. 부분 데이터에 후속 페이지 추가
8. 부모 SHA가 아직 조회되지 않은 경계
9. 삭제된 브랜치 참조가 없는 이력
10. 페이지네이션 및 API 오류

레이아웃 결과가 실제 부모 SHA 관계와 일치하는지 검증합니다. 테스트 라이브러리는 프로젝트 규모에 맞게 최소한으로 선택합니다.

## 10. MVP 완료 조건

- 공개 저장소 URL만 입력해 그래프 조회 가능
- 비공개 저장소를 읽기 전용 PAT로 조회 가능
- Git DAG 분기·병합 관계를 정확하게 표시
- 최신순 / 과거순 전환
- 커밋 정보 Hover/Tap 및 원본 GitHub 이동
- 브랜치 참조 표시와 경로 강조
- 데스크톱 및 모바일에서 사용 가능
- 큰 저장소에서 점진적 로딩과 뷰포트 렌더링
- 오류와 불완전한 조회 상태를 명확히 안내
- 백엔드 없이 정적 웹앱 빌드 가능

## 11. Codex 첫 작업

위 명세에 따라 **저장소 입력 → GitHub API 조회 → 커밋 DAG 모델 → 세로형 Canvas 그래프 표시**를 먼저 구현합니다.

초기에는 기능을 과하게 확장하지 않고, 정확한 관계 표현과 사용성에 집중합니다. 구현 후 테스트·빌드 결과와 남은 제약을 보고합니다.
