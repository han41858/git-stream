# GitStream — Monitor Mode v0.1

## 목적과 범위

일반 모드를 유지하면서 1~4개 GitHub 저장소의 기존 세로형 Git DAG를 한 가로 행에서 관찰한다. 모바일 PWA 가로 화면을 권장하며 데스크톱과 세로 화면도 지원한다. 새로운 백엔드·라이브러리·그래프 엔진·Worker·Service Worker는 도입하지 않는다.

## 진입과 저장소 선택

- 일반 헤더의 분할 아이콘 **Split view**로 선택 창을 연다. 저장한 선택에 현재 저장소가 있으면 순서를 유지하고, 없으면 현재 저장소를 맨 앞에 추가한다. URL에서 복원한 구성은 저장된 기본 선택보다 우선한다.
- 최근 방문 목록을 재사용하거나 `owner/repo`·GitHub URL을 직접 입력해 추가한다. 주소는 기존 `parseRepo`·소문자 변환·커서 보존 로직을 사용한다. 선택 중에는 API를 호출하지 않는다.
- 중복과 4개 초과 선택을 막는다. 선택한 항목은 아래 최근 목록에서 숨기며, 위 목록에서 제거하면 아래에 최근 방문 순서대로 다시 나타난다. 네 개가 선택되면 추가 가능한 최근 목록을 숨긴다.
- **선택 창 위쪽 목록**의 핸들을 마우스·터치로 드래그해 순서를 바꾼다. 키보드에서는 핸들에 포커스를 두고 ↑/↓를 사용한다. 포커스를 유지하며 변경한 위치를 스크린 리더용 상태로 알린다. 이 순서가 분할 화면의 좌우 배치·저장된 선택·공유 링크에 반영된다. 활성 분할 화면에는 드래그 기능을 추가하지 않는다.
- 최소 한 개를 선택해야 **Start split view**와 **Copy link** 버튼이 활성화된다. 선택·추가·제거·정렬·링크 복사는 API 요청을 발생시키지 않는다.
- 선택 창은 Escape·닫기·배경 클릭으로 닫을 수 있고, 키보드 포커스를 창 안에서 이동한 후 기존 진입 버튼으로 돌려준다.
- 모니터 모드 안에는 저장소 편집·브랜치 선택·방향 전환·설정·수동 갱신 UI를 제공하지 않는다.

## URL 구성 공유와 복원

| URL 예시 | 동작 |
| --- | --- |
| `/?repo=han41858/git-stream` | 기존 단일 저장소 화면 |
| `/?repo=han41858/git-stream&repo=octocat/Hello-World` | URL 순서대로 두 저장소 분할 |
| `/?repo=han41858/git-stream&mode=monitor` | 한 저장소로 분할 모드 진입 |

- `repo` 파라미터가 두 개 이상이거나 `mode=monitor`이면 모니터 구성을 읽는다. 기존 파서로 주소를 정규화하고 소문자 변환·중복 제거 후 앞쪽의 유효한 저장소를 최대 네 개까지 사용한다. 중복·잘못된 항목 제거 후 하나만 남아도 모니터 의도를 유지하며, 유효한 항목이 전혀 없으면 빈 일반 화면을 표시한다.
- 파싱은 접근 권한을 확인하지 않는다. 실제 진입에서는 기존 모델로 각 저장소를 열고, 권한·404·네트워크 오류는 해당 열에만 표시한다. 첫 저장소가 실패해도 나머지 열은 동작하며 기존 공통 갱신으로 다시 시도한다. URL을 위한 추가 조회는 없다.
- 일반 모드의 선택 창에만 **Copy link**를 제공한다. 현재 선택과 순서를 반복 `repo` 파라미터로 만들며, 한 개일 때는 `mode=monitor`를 넣는다. 복사 성공은 `Link copied.`, 거부·미지원은 `Could not copy link.`로 안내한다. 복사만으로 모드를 시작하거나 현재 주소를 바꾸지 않는다.
- 공유 링크에는 저장소 이름·순서·모드만 포함한다. 원래 주소의 다른 쿼리·해시·URL 인증 정보는 제거하며 PAT·자동 갱신 주기·디버그·스크롤 상태는 복사하지 않는다. **비공개 저장소 이름도 URL에 노출된다**는 안내를 선택 창에 표시한다. 링크 접근 시에는 수신자의 기존 PAT·인증 정책을 그대로 적용한다.
- 모드·저장소 전환은 브라우저 history에 기록하며 뒤로/앞으로 가기와 새로고침은 URL 구성을 복원한다. 저장된 선택은 URL 구성을 덮어쓰지 않는다. 기존 `?debug=1` 등 현재 탭의 부가 URL 문맥은 앱 안의 이동에서는 유지하지만 공유 링크에서는 제외한다.
- 새 탭에서 모니터 URL을 열면 첫 저장소를 기본 모델로 사용한다. 기존 일반 화면에서 진입한 경우 기본 모델·Canvas·탐색 상태를 보존하고, 복귀 시 그 저장소의 단일 URL로 돌아간다. 새로고침 후에는 URL의 첫 저장소가 복귀 대상이며 이전 탭의 스크롤·브랜치 선택은 공유하지 않는다.
- URL 진입도 현재 창의 레이아웃만 전환한다. Fullscreen API나 새 라우터·라이브러리는 사용하지 않는다.

## 저장과 인증 경계

- localStorage 키는 `gitstream.monitor-repositories`이며 최대 네 개의 정규화된 저장소 **이름 문자열 배열만** 저장한다. PAT·토큰 일부·해시·API 응답·커밋·스크롤 위치는 포함하지 않는다.
- 잘못된 배열·주소·중복 항목은 정리한다. 저장소 접근 실패 시에도 모니터링은 현재 탭의 메모리에서 사용할 수 있다.
- 공개 여부는 최근 방문 이력의 실제 API 메타데이터 분류를 재사용한다. PAT를 쓰지 않는 직접 입력 항목은 공개 메타데이터 조회 성공 후 저장 목록에 반영한다.
- 최초 PAT 등록·교체·삭제 시 비공개 및 공개 여부를 확인할 수 없는 선택을 제거하고, 확인된 공개 선택만 유지한다. 동일 PAT 재적용과 저장된 같은 PAT 복원은 선택을 유지한다. 접근 실패만으로 목록을 삭제하지 않는다.
- 목록 자체가 접근 권한을 보장하지 않는다. 새 토큰으로 다시 조회한 비공개 저장소는 다시 선택·등록할 수 있다.
- 오래된 인증 탭은 적용 토큰과 저장 토큰의 일치 여부를 확인해 다른 인증의 비공개 선택을 표시하거나 덮어쓰지 않는다. 다른 탭의 PAT 변경 이벤트는 모니터 모드와 선택 창을 닫고 선택을 다시 읽는다. 실제 적용 토큰을 몰래 바꾸지는 않는다.
- 최근 방문 목록은 10개로 제한되므로, 공개 분류가 더 이상 남아 있지 않은 선택도 PAT 변경 시 보수적으로 제거될 수 있다. 별도 가시성 데이터베이스나 확인용 API를 추가하지 않는다.

## 레이아웃과 복귀

- 선택한 개수로 너비를 균등 분할한다. 1개는 전체, 2개는 2분할, 3개는 3분할, 4개는 4분할이며 2×2 배치는 없다. 각 열은 `min-width:0`과 독립 세로 스크롤을 사용한다.
- 각 영역 상단에 전체 `owner/repo`를 표시한다. 긴 이름은 말줄임하고 title과 영역의 접근성 이름에는 전체 값을 제공한다.
- 위쪽에는 읽기 전용 공통 타이머와 복귀 아이콘 **Return to single view**만 배치한다. 로고·일반 헤더·일반 상태 패널을 숨긴다. 명시적으로 켠 개발자 진단 UI와 기존 PWA 업데이트 안내는 별도 기존 기능이다.
- **Start split view**는 현재 앱 창을 그대로 분할한다. Fullscreen API 호출이나 전체화면 이벤트 구독은 하지 않는다. 사용자가 원하면 브라우저의 F11 등으로 전체화면을 직접 제어하며 앱의 분할 상태와 독립적이다.
- 복귀 버튼·Escape는 일반 모드로 돌아간다. 브라우저 전체화면을 켜거나 끄는 동작은 앱 모드를 바꾸지 않고, 앱에서 복귀해도 사용자가 설정한 브라우저 전체화면을 종료하지 않는다.
- 강제 화면 회전·방향 잠금은 하지 않는다. Safe Area와 기존 앱 셸의 높이를 사용하며, ResizeObserver가 각 열의 Canvas 크기를 다시 측정한다.

## 그래프와 상세

- 현재 열린 저장소가 포함되면 기존 `History`·`CommitInfoStore`·Canvas 인스턴스를 그대로 사용한다. 진입을 위해 같은 메타데이터를 다시 조회하지 않는다. 현재 브랜치·시간 방향·스크롤·선택을 유지한다.
- 추가 저장소는 독립적인 기존 `History`·`CommitInfoStore`를 생성하고 기존 기본 브랜치 우선순위와 최신순에서 시작한다. 모델·커밋 배열·캐시·선택·스크롤을 저장소 간 공유하지 않는다.
- DAG 계산·레인·색상·브랜치 배지·실제 부모 SHA 관계·태그/릴리즈 아이콘·Actions 링은 기존 렌더러 그대로 사용한다. 추가 저장소도 저장소 메타데이터 성공 시점에 태그·릴리즈·Actions 로딩을 병렬 시작해 첫 화면부터 보이는 커밋의 작업 수를 추적한다.
- 모니터에서는 모든 화면 크기에서 메시지·SHA·작성자를 Canvas에서 숨기고, 전체 열 너비를 그래프에 쓴다. 행 간격은 기존 31px를 유지한다. 텍스트는 노드 선택 시 기존 `CommitDetails`로 확인한다.
- 각 상세 패널을 해당 열 안에 한정한다. 다른 열에서 커밋을 선택해도 기존 열의 선택과 상세를 해제하지 않는다.
- 현재 보이는 미조회 경계만 기존 점진 로딩을 호출한다. 한 열의 스크롤이 다른 열의 과거 이력을 미리 읽지 않는다.
- 최신 위치의 새 커밋 추적·240ms 애니메이션·사용자 조작 시 추적 중단·과거 탐색의 SHA 앵커 보정은 기존 `scrollPosition`과 Graph 로직을 저장소마다 적용한다.
- 모니터 대상에서 제외된 기존 일반 그래프는 DOM과 상태를 보관하면서 Canvas 렌더링·보이는 커밋 조회를 멈춘다. 종료 시 원래 단일 모드 URL과 그래프로 복귀한다.

## 공통 갱신과 오류

- 기존 `RefreshLoop` **한 개만** 스케줄을 소유한다. 일반 설정의 자동 갱신 ON/OFF와 30초(PAT 필요)·1분·5분을 공유하며 별도 주기는 추가하지 않는다.
- 공통 시점마다 선택한 저장소의 갱신을 시작한다. 느린 작업이 끝날 때까지 타이머를 붙잡지 않고, 각 모델이 응답을 받는 대로 화면을 반영한다.
- 초기 로딩·갱신·점진 로딩 중인 저장소는 중복 갱신을 건너뛴다. 다른 저장소는 다음 공통 주기에도 갱신할 수 있다.
- 기존 SHA 커밋 캐시·ETag/304·중복 요청 공유·증분 브랜치 갱신·완료 Actions 추적 중단을 유지한다. 저장소별 HTTP 풀과 기존 재시도 처리를 사용한다.
- 같은 PAT의 한도를 독립 쿼터로 취급하지 않는다. 어느 열에서든 확인한 Rate Limit 재시도 시각을 세션 전체에 즉시 적용해 갱신·추가 경계/상세 요청을 기다리게 한다. 이미 전송된 요청은 도착할 수 있다. 새 인증으로 바꾸면 이전 인증의 대기 시각과 늦은 결과는 무효화한다.
- 네트워크·권한·404·부분 메타데이터 오류는 해당 열에 표시하고 다른 열을 유지한다. 초기 메타데이터 실패는 다음 공통 주기에 다시 시도한다.
- 타이머는 기존 SVG 원형 진행 표시와 CSS 애니메이션을 재사용한다. 클릭 동작과 별도 JS 타이머는 없으며, 갱신 중 회전과 일시 중지 상태를 표현한다.
- 백그라운드·오프라인에서는 기존 스케줄을 멈추고, 기한이 지난 복귀는 한 번 갱신한다.
- 종료 시 추가 열의 요청·구독을 취소하고 정리한다. 일반 모드에서 계속 사용하는 현재 저장소의 작업은 유지하며, 같은 `RefreshLoop`를 단일 저장소 범위로 되돌린다.

## PWA와 측정

정적 앱 셸 캐싱과 업데이트 정책은 바꾸지 않는다. API 응답·PAT를 Service Worker로 캐시하거나 백그라운드 동기화를 추가하지 않는다. PWA의 기본 시작 주소 `/`는 일반 모드이며 저장한 선택을 다시 사용할 수 있다. 명시적 모니터 URL을 열거나 그 주소에서 새로고침하면 분할 구성을 복원한다.

기존 개발자 디버그 모드의 HTTP 종류·상태·캐시·동시 요청·갱신·DAG·Canvas 측정을 사용한다. 최근 20개 표본과 진단 복사는 기존 정책을 따르며 저장소 이름이나 선택 목록을 측정 데이터에 추가하지 않는다. Graph 요약은 마지막으로 렌더링한 그래프의 값이고, 요청·타이밍 표본은 여러 그래프에서 모인다. 디버그가 꺼져 있으면 상세 측정용 스냅샷을 만들지 않는다.

## 알려진 제약과 제외

- 설치된 iOS/Android PWA, 실제 가상 키보드·Safe Area·저사양 기기 성능, VoiceOver/TalkBack 낭독은 실기기에서 추가 확인해야 한다. OS 상태 표시줄과 사용자가 직접 선택하는 브라우저 전체화면은 플랫폼 정책을 따른다.
