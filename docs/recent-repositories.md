# 최근 방문 저장소 자동완성

## 목적과 범위

기존 저장소 입력창에서 성공적으로 방문한 GitHub 저장소를 다시 연다. 최근 10개를 현재 브라우저의 localStorage에 보관하고, 검색은 이 목록 안에서만 수행한다. 새로운 라이브러리·백엔드·원격 검색·추가 GitHub 권한은 사용하지 않는다.

## 데이터와 성공 기록

- 키: `gitstream.recent-repositories`. PAT 키 `gitstream.github-token`과 분리한다.
- JSON 배열의 각 항목은 `repository`(소문자 `owner/repo`), `visibility`(`public`/`private`), `visitedAt`(성공 시각의 Unix 밀리초)만 포함한다.
- 중복 저장소는 가장 최근 항목으로 합치며 최근순으로 최대 10개를 유지한다. 유효하지 않은 항목·시각·공개 여부와 알 수 없는 필드는 제거한다.
- `History.open()`이 기존 `/repos/{owner}/{repo}` 응답을 받고 취소되지 않은 것을 확인한 시점에 기록한다. 주소 입력·추천 검색 자체는 기록하지 않는다.
- URL `?repo=` 접속·검색 버튼·Enter·데모·추천 선택·초기 메타데이터 재시도도 같은 성공 경로를 사용한다. 이후 브랜치·커밋 조회 실패와 메타데이터 조회 성공은 구분한다.
- 잘못된 주소나 메타데이터의 404·401·403·네트워크 오류, 취소된 이전 요청은 방문 항목을 만들지 않는다. `private`가 실제 boolean인 API 메타데이터만 공개 여부의 근거로 사용한다. PAT 사용 여부나 이름으로 추정하지 않는다.
- 자동/수동 갱신의 기존 메타데이터 응답은 이미 저장된 항목의 공개 여부만 갱신한다. 방문 시각은 바꾸지 않고 삭제한 항목을 다시 만들지 않는다. 현재 공개 여부를 확인하기 위한 요청은 추가하지 않는다.
- 추천에서 현재 보고 있는 저장소를 다시 고르면 기존 그래프·선택·요청을 유지하고 방문 시각만 갱신한다. 기존 입력값으로 직접 Enter·검색하는 동작은 유지한다.

## PAT 생명주기

| 상황 | 공개 방문 이력 | 비공개 방문 이력 |
| --- | --- | --- |
| 최초 PAT 등록·다른 PAT 적용·PAT 삭제 | 유지 | 이전 이력 제거 |
| 동일 PAT 재적용 | 유지 | 유지 |
| 새 실행에서 같은 저장된 PAT 복원 | 유지 | 유지 |
| 만료·권한 오류 | 유지 | 유지, 다음 접근 성공을 보장하지 않음 |

기존 적용 토큰과 새 토큰의 값을 메모리에서 비교하고, 인증 변경으로 저장소를 다시 열기 전에 비공개 이력을 제거한다. 새 PAT로 같은 비공개 저장소의 메타데이터 조회가 성공하면 다시 등록될 수 있다. 기존 PAT 저장·복원·오류 안내·API 취소·그래프 초기화는 그대로 사용한다.

PAT 자체·일부·해시를 방문 데이터에 저장하지 않는다. 새 실행에서는 PAT 복원을 인증 변경으로 취급하지 않는다. 공개 저장소를 PAT로 조회해도 공개 이력이다.

다른 탭에서 저장 데이터가 바뀌면 `storage` 이벤트로 목록을 다시 읽는다. 적용 중인 PAT와 브라우저에 저장된 PAT가 다른 오래된 인증 탭은 비공개 추천을 표시하거나 새 비공개 이력을 기록하지 않는다. 공개 항목을 갱신할 때도 최신 저장 데이터를 읽어 다른 탭에서 지운 비공개 항목을 되살리지 않는다. PAT 저장에 실패해 이번 탭에서만 다른 토큰을 사용하는 경우에도 비공개 이름을 이전 저장 토큰의 이력으로 남기지 않는다. 이 보호는 현재 탭의 실제 API 인증을 변경하지 않는다.

## 입력·목록·접근성

- 포커스 시 목록을 표시한다. 빈 값은 최근 항목 전체, 입력 중에는 대소문자 무관 부분 문자열 검색 결과만 보인다. GitHub URL 입력도 로컬 저장소 이름으로 검색한다. 이력·일치 항목이 없거나 저장소를 사용할 수 없으면 숨긴다.
- 항목은 최근 방문 아이콘·저장소 이름·개별 삭제 버튼만 표시한다. 설명·통계·공개 여부 표시·별도 최근 저장소 화면은 추가하지 않는다.
- 클릭·탭·활성 항목 Enter는 주소를 반영하고 기존 저장소 열기를 즉시 호출한다. 자동완성을 닫고 기존 제출 동작처럼 입력 포커스를 해제한다.
- 선택 전 Enter는 기존 입력값을 제출한다. ArrowDown/ArrowUp은 활성 항목을 이동하고 양 끝에서 순환한다. Escape는 목록을 닫고, Tab의 기본 포커스 이동은 막지 않는다. 입력 중 커서·선택 위치는 기존 `lowercaseField()`로 보존한다.
- 바깥 클릭·포커스 이동·다른 팝업 열기는 목록을 닫는다. 입력 지우기는 그래프를 유지한 채 전체 최근 목록을 다시 보여준다.
- 입력창에 ARIA combobox 관계와 활성 항목 ID를 제공한다. 각 항목에 별도 삭제 버튼이 있으므로 상호작용 컨트롤을 허용하는 `grid` 팝업과 `row`/`gridcell`을 사용한다. 삭제 버튼의 접근성 이름에는 저장소 이름을 포함한다.
- 개별 삭제와 하단 **Clear history**는 확인 팝업 없이 저장 데이터만 지우고 입력 포커스를 유지한다. 그래프·PAT·설정은 변경하지 않는다. 새 메타데이터 조회 성공 후에는 다시 기록한다.

## 모바일·PWA·보호

목록을 기존 입력 폼 바로 아래에 배치하고 폭을 폼 안으로 제한한다. 긴 이름은 말줄임하고 전체 이름은 버튼 title에 남긴다. 항목과 삭제·전체 삭제는 최소 44px 높이를 사용한다. `visualViewport`의 높이·스크롤·크기 변경과 Safe Area를 반영해 목록 높이를 제한하고 내부 스크롤을 제공한다.

PWA 재실행에서도 같은 브라우저 저장소의 이력을 복원한다. 브라우저와 설치 앱의 저장소 공유 여부는 플랫폼 정책을 따른다. Service Worker에 이력 저장을 추가하지 않으며 GitHub API·PAT 캐시 정책은 바꾸지 않는다.

이력은 외부 서버·분석 서비스·디버그 로그·진단 복사에 보내지 않는다. 저장소 이름은 민감할 수 있으므로 전체 삭제를 제공한다. localStorage 읽기·쓰기 오류가 나면 목록을 비활성화하고, 가능하면 이력 키를 제거한다. 저장소 입력·인증·그래프는 계속 사용할 수 있다. 브라우저가 삭제까지 차단하면 저장 데이터 제거를 보장할 수 없으므로 저장소 접근이 막힌 동안 이 기능은 꺼진 상태를 유지한다.

## 구현과 검증

- `RecentRepositories.ts`: 검증·정렬·저장·검색·인증 변경·삭제. UI와 분리하고 저장소와 시계를 주입해 테스트한다.
- `history.ts`: 기존 메타데이터 성공 시 콜백만 제공한다. 방문용 요청이나 인증 코드는 추가하지 않는다.
- `RepositoryInput.tsx`: 기존 폼과 커서 복원 로직, 로컬 목록·키보드·터치·ARIA 처리.
- `main.tsx`: 기존 PAT 생명주기에 이력 정리를 연결하고 현재 저장소 선택의 중복 조회를 방지한다.

자동 테스트는 정규화·중복·10개 제한·복원·잘못된 저장 데이터·토큰 변경/유지·공개 여부 변경·삭제·저장 오류·다른 탭의 오래된 인증 문맥을 검증한다. 실제 History를 연결해 메타데이터 성공/실패/취소와 API 요청 수 동일성을 확인한다. 브라우저 검증은 입력·선택·삭제·키보드·커서·모바일 뷰포트·PWA 캐시 재실행과 인증 회귀를 확인하며 실기기 검증과 구분해 보고한다.

### 구현 시 검증 결과 (2026-10-31)

- `npm test`: 244개 통과. 이 기능의 저장소 단위 테스트 18개와 History 통합 테스트 8개를 포함한다.
- `node --test --test-isolation=none .github/scripts/*.test.mjs`: 기존 릴리즈 테스트 26개 통과. `npm run build` 성공.
- Production 빌드를 Chromium에서 실행해 23개 시나리오 묶음을 통과했다. GitHub API는 성공·실패·공개 여부 변경을 재현하는 테스트 응답을 사용했다. 입력·필터·삭제·현재 저장소 재선택은 추가 요청 0회를 확인했다.
- 실제 공개 저장소 `han41858/git-stream`도 조회해 메타데이터 HTTP 200·공개 이력 저장·그래프 표시를 확인했다. 최초 로딩은 기존 API 요청 10회, 현재 저장소 추천 재선택은 추가 요청 0회였다. 브라우저의 외부 접속 제한 때문에 세션 프록시를 통한 TLS 검증 중계로 실제 GitHub 응답을 전달했으며, 이 확인에는 테스트 응답을 사용하지 않았다.
- 320·390·430·1280px에서 목록 폭·44px 터치 영역·Tab·팝업 닫기를 확인했다. 모바일 높이를 310px로 줄여 목록 내부 스크롤을 확인하고, 터치·마우스 선택과 키보드 삭제를 각각 검증했다.
- 실제 Service Worker가 제어하는 페이지를 오프라인으로 다시 열어 공개·비공개 이력 복원과 삭제를 확인했다. 자동 갱신은 테스트 시계를 61초 진행해 확인했다.
- 설치된 iOS/Android PWA, 실제 가상 키보드와 Safe Area, VoiceOver/TalkBack/NVDA의 음성 안내는 실기기에서 별도 확인이 필요하다. 플랫폼 간 브라우저/PWA 저장소 공유는 보장하지 않는다.
