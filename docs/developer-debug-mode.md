# GitStream 개발자 디버그 모드

## 활성화와 UI

- 개발 서버에서는 `Ctrl + Shift + D`로 패널을 여닫는다. 처음 누르면 측정을 켜고 패널을 연다. 패널을 닫아도 측정은 유지되며 **Disable debug**로 완전히 끈다.
- 개발·Preview·Production 정적 빌드 모두 `?debug=1`로 측정을 켤 수 있다. 예: `/?repo=owner%2Frepository&debug=1`. 저장소를 변경해도 다른 쿼리와 URL fragment를 유지한다.
- 기본 상태에서는 디버그 진입 버튼이 없다. 활성화되면 오른쪽 아래 작은 버튼을 표시한다. 패널은 비모달이며 네 모서리로 위치를 선택할 수 있고 데스크톱에서는 크기 조절이 가능하다. 모바일에서는 화면 너비 안에 맞춘다.
- URL 옵션은 진단 활성화 수단이며 인증이나 접근 권한을 부여하지 않는다. PAT·API 권한·캐시 정책·갱신 주기·요청 수를 변경하지 않는다.
- 패널 내부 클릭과 Escape는 일반 앱의 선택·팝업 상태를 바꾸지 않는다.

### HTTP와 Rate Limit

- HTTP 수는 공통 클라이언트에서 실제 시작한 **fetch 호출 수**다. 대기열, 캐시 반환, 동일 진행 요청의 공유는 HTTP로 세지 않는다. 이미 취소된 signal로 시작한 호출도 별도 취소로 처리하며 전송 수에는 더하지 않는다.
- 브라우저 내부 캐시, 리다이렉트, CORS 사전 요청, TCP 패킷은 이 수치의 범위가 아니다. API 시간은 대기열 시간을 제외하며 본문 파싱을 포함한다. 상태 코드를 받기 전 실패·취소는 `network` 상태로 집계한다.
- `requestActivity`의 기존 진행 요청 카운터를 재사용한다. 취소 신호가 오면 기존 로딩 표시와 동일하게 진행 수를 내린다. 대기열은 별도 구독으로 분리한다. 디버그를 도중에 켠 경우 이미 시작한 요청은 상세 이력 없이 현재 진행 수에만 나타날 수 있다.
- `X-RateLimit-Limit/Remaining/Used/Reset/Resource`의 허용된 수치·리소스만 읽는다. 헤더가 없거나 브라우저에서 노출되지 않으면 `unknown`이다. 추가 Rate Limit API를 호출하지 않는다.
- 같은 리소스·초기화 구간에서 관측한 `Used`의 최대·최소 차이를 `observedUsedDelta`로 표시한다. 첫 관측 이전 소모량은 알 수 없고 다른 탭·프로세스의 트래픽도 포함될 수 있다. 이는 HTTP 건별 과금량이나 이 앱만의 정확한 할당량 소모량이 아니다. 304 수도 HTTP 수와 따로 표시한다.
- 동시에 같은 경로·쿼리에 fetch가 발생하면 중복 **후보**로 센다. 인증 세션이 다르거나 해시가 충돌한 경우 등 정당한 중복도 있을 수 있으므로 불필요한 요청으로 단정하지 않는다. 기존 in-flight 공유 횟수는 별도 집계한다.

### 갱신과 변경 수

- `initial`, `manual`, `auto`를 구분하고 `refresh-N` ID를 부여한다. 저장소 로딩과 초기 메타데이터의 기존 실행 순서를 유지하며 완료를 합산한다. 재시도·스크롤·권한 확인 등 독립 작업은 API 전역 집계에 나타나며 갱신에 강제로 합치지 않는다.
- 동시에 수행되는 갱신·상세 조회의 요청은 signal 및 명시적인 작업 참조로 구분한다. 기존 요청을 공유할 때는 공유 수를 올리며 HTTP를 이중 계상하지 않는다.
- 최초 로딩은 빈 데이터와 비교한다. 수동·자동 갱신은 전후 메모리 모델을 비교한다. 커밋 추가·변경·제거, 브랜치 생성·변경·삭제, 태그·릴리즈·Actions 변경을 집계한다. Actions에는 로딩된 Job 상태와 재실행 attempt 변화도 포함한다.
- 비교용 키·수치 해시는 로컬 메모리에서만 사용하고 진단·Console에는 **변경 개수만** 내보낸다. 해시 충돌 가능성이 있으며, API에서 아직 로딩하지 않은 데이터·이미 기존 모델이 버린 응답은 관측할 수 없다. 이 기능은 기존 모델의 데이터 반영 정책을 바꾸지 않는다. 변경 수는 갱신 전후 관측값이므로 같은 시간에 진행된 스크롤 로딩·상세 조회의 모델 변경도 포함될 수 있다. HTTP 작업 귀속과 별개인 관측 한계다.
- 갱신 완료 시 Console에 요약을 한 번 출력한다. React의 정상 commit/effect를 포함하기 위해 요약 출력만 100ms 늦추며 네트워크·작업 소요 시간에는 이 지연을 더하지 않는다. 같은 커밋 배열에 연결된 DAG·Canvas 작업을 완료 후 최대 100ms까지 귀속한다. 그 이후 그리기는 별도 샘플로 기록한다.
- Canvas 시간은 CPU에서 그리기 명령을 실행한 시간이며 GPU 완료 시간·FPS가 아니다. `layout()` 외의 색상·라벨·좌표 계산, React 전체 렌더 시간도 DAG 시간에 포함하지 않는다. 개발 StrictMode는 effect·계산을 추가 실행할 수 있으므로 Production 빌드와 숫자가 다를 수 있다.

## 보관·복사·데이터 보호

- HTTP 요청, 갱신, DAG 계산, Canvas 그리기 **각각 최근 20개**를 메모리에 유지한다. 세션 누적 수는 별도로 유지한다. 새로고침·Reset·Disable debug 시 상세 측정과 누적 수를 지운다. 앱 데이터·캐시·요청에는 영향을 주지 않는다.
- **Copy diagnostics**는 허용된 필드만으로 JSON을 만든다. 수치 집계, 고정된 API 종류, 상태 코드, 갱신 ID·종류, 시간, Rate Limit 수치, 현재 진행·대기 수만 포함한다.
- 저장소·브랜치·태그 이름, SHA, 커밋 메시지·작성자, URL·쿼리, PAT, Authorization, ETag 원문, 오류 메시지, 원본 응답을 복사하거나 Console에 기록하지 않는다. Console 버튼은 같은 수치 스냅샷을 제공한다. 클립보드 접근이 불가능하면 오류를 표시하고 Console로 확인할 수 있다.
- 상세 로그는 DevTools Console에서 `[GitStream debug]`로 찾을 수 있다. 분석 서버, 외부 전송, 분석 라이브러리, 영속 DB나 디버그용 localStorage를 사용하지 않는다.

## 비활성 상태의 비용

- 상세 시계 읽기, 경로 해시·중복 검사, 전후 데이터 스캔, 측정 샘플 생성, 로그, 측정 알림 타이머·구독 렌더를 수행하지 않는다. 측정 지점의 활성 여부 검사와 대기 수 정수 갱신만 남는다.
- 일반 그래프는 측정 상태를 구독하지 않는다. 패널을 열 때만 수치를 구독하며 상세 스냅샷 알림은 최대 250ms마다 합친다. 숨긴 탭에서는 측정 알림을 중단하고 돌아오면 최신 수치를 반영한다. 기존 자동 갱신의 숨김·오프라인 중단 정책을 유지한다.
- 닫힌 패널에서는 상세 측정·최근 기록·Console 요약은 계속한다. 완전히 중단하려면 Disable debug를 사용한다. 진단 UI와 계측 코드의 정적 번들 크기 비용은 남는다.

## 검증

- `npm test`: 기존 테스트 및 디버그 측정·보안·20개 보관·비활성 비용·304·변경·실패·취소·동시성·백그라운드 알림·수동/자동 구분 회귀 검사.
- `npm run build`: 타입 검사와 Vite 정적 Production 빌드.
- 브라우저에서는 `?repo=...&debug=1`로 로딩, 수동 갱신, 미변경 304, 커밋·브랜치·태그·릴리즈·Actions 변화, 진단 복사, 팝업 상태 유지, 모바일, 숨김·복귀, 대형 저장소 점진 로딩·스크롤을 확인한다. 디버그 OFF 동일 흐름과 API 요청 수를 비교한다.
- 결정적 API fixture의 검증은 실제 GitHub의 Rate Limit 소모량·비공개 저장소 권한·실제 대형 저장소 성능을 입증하지 않는다. 실제 서비스와 배포 환경 확인은 별도 검증으로 남긴다.
